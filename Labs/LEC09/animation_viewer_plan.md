# Sonic Sprite Animation Viewer 제작 계획

## 1. 목표

`sonic-sprite.png`를 기준으로, 10개의 애니메이션을 행 단위로 분류해 화면에 재생하는 애니메이션 뷰어를 만든다. 

핵심 목표는 다음과 같다.

- 스프라이트 시트의 실제 프레임 구조를 확인한다.
- 행 단위로 10개 애니메이션을 분리한다.
- `pico2d`를 사용해 프레임을 한 장씩 출력한다.
- 키 입력으로 애니메이션을 직접 선택한다.
- 자동 전환은 피하고, 천천히 확인할 수 있게 한다.

---

## 2. 사용 자산

- 파일: `sonic-sprite.png`
- 위치: `Labs/LEC09/sonic-sprite.png`
- 도구: `pico2d`, `load_image`, `clip_draw`, `get_events`

현재까지 확인한 정보:

- 이미지 크기는 약 `399 x 525`로 추정된다.
- 실제 스프라이트 시트는 행 단위로 분리된 구조를 가질 가능성이 높다.
- 총 12개 행으로 나누는 방식을 가정하면, 실제 애니메이션은 `row 2 ~ row 11`만 사용하고 `row 0, 1`은 비어 있거나 경계 영역일 가능성이 높다.

> 이 문서는 원본 시트의 실제 기준을 확인하기 전의 제작 계획이며, 구현 시에는 행/열 구조를 정밀하게 검증하면서 조정한다.

---

## 3. 기본 가설: 12행 구조

이미지 시트를 12행으로 나눈다고 가정하면, 각 행은 다음 용도로 사용할 수 있다.

- row 0: 여백 또는 미사용 영역
- row 1: 여백 또는 미사용 영역
- row 2: 애니메이션 1
- row 3: 애니메이션 2
- row 4: 애니메이션 3
- row 5: 애니메이션 4
- row 6: 애니메이션 5
- row 7: 애니메이션 6
- row 8: 애니메이션 7
- row 9: 애니메이션 8
- row 10: 애니메이션 9
- row 11: 애니메이션 10

즉, 실질적으로는 10개 애니메이션이 `2~11` 범위의 행에 배치된 구조로 보는 것이 가장 자연스럽다.

## 5. 프레임 구조 설계

### 5.1 프레임 좌표 계산

각 행은 여러 열의 프레임으로 구성되며, 다음처럼 계산한다.

```python
def frame_rect(row, col):
    left = col * FRAME_WIDTH
    top = row * FRAME_HEIGHT
    return left, top, FRAME_WIDTH, FRAME_HEIGHT
```

여기서:

- `row`: 스프라이트 시트의 행 번호
- `col`: 프레임 열 번호
- `FRAME_WIDTH`, `FRAME_HEIGHT`: 프레임 한 칸의 크기

### 5.2 가정된 프레임 구성

- 한 행당 대략 4~12개의 프레임이 들어갈 수 있음
- 각 동작은 행 전체를 사용하지 않고, 필요한 프레임만 추출해서 재생
- 프레임 수는 동작마다 달라질 수 있으므로, 각 애니메이션마다 프레임 리스트를 따로 구성

예시:

```python
ANIMATIONS = {
    "idle": [frame_rect(2, 0), frame_rect(2, 1), frame_rect(2, 2)],
    "run": [frame_rect(3, 0), frame_rect(3, 1), frame_rect(3, 2), frame_rect(3, 3)],
    "jump": [frame_rect(4, 0), frame_rect(4, 1), frame_rect(4, 2)],
}
```

## 6. 구현 방식

### 6.1 전역 변수

```python
CANVAS_WIDTH = 800
CANVAS_HEIGHT = 600
FRAME_DELAY = 0.18
DISPLAY_SCALE = 2.0
SPRITE_PATH = "sonic-sprite.png"
```

### 6.2 핵심 함수

- `frame_rect(row, col)`: 프레임 좌표 계산
- `load_animation_groups()`: 10개 애니메이션을 묶어서 정리
- `handle_keydown()`: 키 입력 처리
- `update_animation()`: 시간 기반으로 다음 프레임으로 이동
- `draw_frame()`: 현재 프레임을 화면 중앙에 그리기

### 6.3 키 입력 설계

- `1`: 처음 표시되는 애니메이션을 재생하며 왼쪽에서 오른쪽까지 이동
- `2`: run 애니메이션을 화면 중앙에서 재생
- `3`: jump
- `4`: spin
- `5`: slide
- `6`: hurt
- `7`: crouch
- `8`: climb
- `9`: hang
- `0`: die
- `Esc`: 종료

`1` 이동은 처음 표시되는 애니메이션을 사용하고 초당 240픽셀 속도로 진행한다. 이동이 끝나면 캐릭터는 오른쪽 끝에 멈추며, `1`을 다시 누르면 왼쪽 시작점에서 이동을 다시 시작한다.

---

## 7. 자동 전환 여부

자동 전환 기능은 사용하지 않는다.

- 처음에는 기본 애니메이션만 보여준다.
- 사용자가 키를 누르면 원하는 동작을 선택한다.
- 프레임 전환 사이에 딜레이를 두어 시트를 천천히 확인할 수 있게 한다.
- 연속 재생보다 수동 확인을 우선으로 설계한다.

권장 값:

```python
FRAME_DELAY = 0.15
TRANSITION_DELAY = 0.7
```

## 8. 구현 순서

1. `sonic-sprite.png` 경로를 확인한다.
2. 이미지 크기와 행/열 구성을 추정한다.
3. 12행 구조를 가정하고 `row 2 ~ 11`을 실제 애니메이션 구역으로 본다.
4. `frame_rect()` 함수를 만든다.
5. 각 애니메이션별 프레임 리스트를 구성한다.
6. `pico2d` 창을 연다.
7. 스프라이트 시트를 로드한다.
8. 현재 선택된 애니메이션과 프레임 인덱스를 관리한다.
9. 키 입력 이벤트를 처리한다.
10. 한 프레임마다 시간 차이를 계산해 다음 프레임으로 이동한다.
11. 현재 프레임을 중앙에 그린다.
12. 자동 전환을 제거하고 딜레이를 조절한다.
13. `Esc`와 창 닫기 이벤트를 처리한다.
14. 프레임이 자연스럽게 보이는지 확인한다.
15. 10개 애니메이션이 모두 잘 나오는지 점검한다.
16. 행 번호와 애니메이션 매핑을 다시 확인한다.
17. 프레임 수가 적절한지 확인한다.
18. 화면 크기와 스프라이트 비율을 조정한다.
19. 전체 동작을 다시 점검한다.
20. 최종 문서와 코드 상태를 정리한다.
21. 구현 중 발생한 문제를 기록한다.
22. 최종 계획을 검토하고 다음 단계로 넘어간다.
